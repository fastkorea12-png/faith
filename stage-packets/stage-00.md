# 00 본관 스테이지 패키지 — 조작된 사건파일

## 1. 스테이지 계약 (Stage Contract)

| 항목 | 확정 내용 |
|---|---|
| 대상 | 대학생, 팀당 3~6명 (총 5팀 동시 진행) |
| 목표 시간 | 12~15분 (오프닝 브리핑 및 사건 진입 포함 20분) |
| 현장 장소 | 본관 접수대 및 중앙 로비 |
| 퍼즐 장르 | 오프닝 사건 브리핑 / 다중 문서 감식 / 모순 추리 |
| 핵심 질문 | 이미 본관에 도착했으나 최종 목적지가 미기록된 우리는 누구인가? |
| 물리 장치 | 물리 자물쇠 없음. 대신 본관 로비에 숨겨진 알파벳 암호 카드 A~E 5장을 찾아 웹에 4자리 암호를 입력해야 기록 5건의 내용이 화면에 드러난다. |
| 웹 기록 감식 정답 | 거짓 기록 3건 선택 (`stampA` 도장 기록, `deskC` 접수대 기록, `numberD` 사건 번호 기록) — 단, 5건 모두 암호로 복원한 뒤에만 선택 가능 |
| 정체성 웹 입력 | `나그네` |
| 결과 키워드 | `나그네` (키워드 카드 00 수령) |
| 완료 코드 | `PILGRIM-00` (활동 페이지 입력) |
| 핵심 의미 | 본관은 최종 목적지가 아닌 출발/접수 지점임을 깨닫고, 세상의 도착 명단에서 벗어나 "아직 길 위에 있는 나그네"로서의 첫 정체성을 확립한다. |

> [!IMPORTANT]
> `나그네`와 `PILGRIM-00`은 역할과 용도가 완전히 분리되어 있다. `나그네`는 최종 05 예배당에서 조합할 실물 키워드 카드이며, `PILGRIM-00`은 활동 페이지(`activity.html`)에 입력하는 해금 코드다.

## 2. 플레이어 경험 및 서사 개요

참가자는 본관 로비에서 QR을 스캔해 `game.html?stage=case`에 접속한다. 웹 화면에는 `현장 사건 메모 (CASE H-11-13)`가 처음부터 보이지만, 접수 기록 5건(`stampA`~`timeE`)은 전부 잠겨 있다. 로비 곳곳에 숨겨진 **알파벳 암호 카드 A~E** 5장을 찾아야만 각 기록의 실제 문장이 화면에 드러난다. 카드에는 알파벳과 4자리 숫자만 인쇄되어 있고, 기록 문장 자체는 종이에 존재하지 않는다 — 오직 웹 화면에서만 복원된다.

### 서사적 긴장감과 반전
사건 메모에는 "도착한 팀은 접수 명단에서 사라지며, 아직 길 위에 있는 팀만 이름을 남긴다"는 역설적 지침이 적혀 있다. 다섯 기록을 모두 복원한 뒤, 참가자들은 이 메모와 정면으로 모순되는 거짓 기록 3건을 가려내야 한다. 거짓 기록을 제거하면 진실된 2건의 기록과 함께 사건번호 `H-11-13`이 단순한 문서 번호가 아니라 **히브리서 11장 13절**("또 땅에서는 나그네와 외국인임을 증언하였으니")을 가리키는 위치 좌표임을 깨닫게 된다.

### 팀별 전용 암호 (5팀 동시 운영 시 혼선 방지)
5개 팀이 같은 로비에서 동시에 카드를 찾으므로, 팀마다 서로 다른 4자리 암호를 쓴다(같은 기록이라도 A팀 카드와 B팀 카드의 숫자가 다르다). 다른 팀이 외친 숫자를 엿들어도 자기 팀 카드에는 소용없다. 팀별 정확한 암호값은 `print-materials.html`의 "00 본관 5개 팀별 독자 보물찾기 암호 카드 마스터(A1~E5)" 표를 그대로 쓰며, 웹은 다섯 팀의 암호를 모두 정답으로 인정한다(팀 로그인/식별 없이도 동작).

## 3. 팀 분업 구조 & 5팀 동시 운영 사양

5개 팀(A~E조)이 본관 접수대에서 동시에 시작하므로, 팀 내 역할을 명확히 분담하여 병목을 방지한다.

| 역할 | 담당 행동 | 반드시 공유할 정보 |
|---|---|---|
| 사건 기록관 | 웹 화면 접속(`game.html?stage=case`) 및 현장 사건 메모(CASE H-11-13) 낭독 | 접수시각 11:13, H 보존 원칙, 미도착/접수지점 조건 |
| 카드 수색관 A | 로비 전반부(예: 소파·게시판 주변)에서 알파벳 카드 2~3장 수색 | 찾은 카드의 알파벳과 4자리 암호 |
| 카드 수색관 B | 로비 후반부(예: 책장·안내데스크 주변)에서 알파벳 카드 2~3장 수색 | 찾은 카드의 알파벳과 4자리 암호 |
| 암호 입력관 | 웹 화면에서 각 카드의 알파벳 슬롯에 암호를 입력해 기록 복원 | 다섯 기록이 모두 복원됐는지 여부 |
| 구절 해독관 | 사건번호 H-11-13과 히브리서 11:13 연계 추리 | 위치 지표 `11:13` 및 성경적 정체성 단어(`나그네`) 추출 |
| 종합 검증 & 선언관 | 다섯 기록 복원 후 거짓 기록 3건 확정 및 정체성 입력 | 거짓 3건 확정 후 최종 키워드(`나그네`) 및 코드(`PILGRIM-00`) 확인 |

### 5팀 동시 운영 병목 방지책
- **팀별 전용 암호**: A~E조는 서로 다른 4자리 암호 세트를 쓰므로(§2 참고), 같은 로비에서 5팀이 동시에 카드를 찾아도 서로의 진행을 방해하거나 답을 가로챌 수 없다.
- **카드 배치 분산**: 팀별 카드 5장을 서로 30~50cm씩 어긋난 위치에 숨겨 다섯 팀의 카드가 한곳에 뭉치지 않게 한다. 카드 뒷면에 팀 라벨(A~E)을 인쇄해 다른 팀 카드를 주웠을 때 즉시 식별하고 제자리에 돌려놓을 수 있게 한다.

## 4. 현장 단서 및 퍼즐 메카니즘 상세

### 4.1 제공 단서 세트

1. **현장 사건 메모 (CASE H-11-13)**:
   - 접수 시각: `11:13` | 조사팀 상태: `미도착` | 현재 위치: `본관 접수대` | 최종 목적지: `미기록`
   - 핵심 지침:
     - 도착한 팀은 접수 명단에서 사라진다.
     - 아직 길 위에 있는 팀만 이름을 남긴다.
     - 기록자는 사건번호 앞의 **H**를 절대로 지우지 말라고 했다.
     - 11:13은 시간이 아니라, 기록을 여는 위치 좌표다.
     - 본관 접수대는 목적지가 아니라 출발/접수 지점이다.

2. **알파벳 암호 카드 A~E (현장 실물, 보물찾기)**:
   - 로비 5곳에 숨겨진 작은 카드. 각 카드에는 알파벳 하나(A~E)와 팀 전용 4자리 숫자만 인쇄되어 있다. 기록 문장은 카드에 없다.
   - 카드 A = `stampA`(도장 기록), B = `listB`(명단 기록), C = `deskC`(접수대 기록), D = `numberD`(사건 번호 기록), E = `timeE`(시각 기록)에 대응한다.
   - 팀별 정확한 숫자값은 §5 및 `print-materials.html`의 A1~E5 매트릭스를 따른다(팀마다 다른 숫자, 웹은 5팀 숫자를 모두 인정).

3. **접수 기록 카드 5종 텍스트 & 진위 판정 (해당 알파벳 암호 입력 시 웹 화면에 표시됨)**:
   - `stampA` (도장 기록): "조사팀은 11:13에 목적지 본향 도착 확인 도장을 받았다." $\rightarrow$ **거짓 (false)** (사건 메모: 본관은 목적지가 아니며 미도착 상태임)
   - `listB` (명단 기록): "미도착 명단에는 아직 길 위에 있는 조사팀의 이름만 남는다." $\rightarrow$ **진짜 (true)** (사건 메모와 완전 일치)
   - `deskC` (접수대 기록): "본관 접수대는 조사팀의 최종 목적지로 등록되었다." $\rightarrow$ **거짓 (false)** (사건 메모: 접수대는 출발 지점일 뿐임)
   - `numberD` (사건 번호 기록): "사건 번호 H-11-13의 H는 오기이므로 지워도 된다." $\rightarrow$ **거짓 (false)** (사건 메모: H를 절대로 지우지 말 것)
   - `timeE` (시각 기록): "11:13은 조사팀이 도착한 시각이 아니라, 기록을 여는 위치다." $\rightarrow$ **진짜 (true)** (사건 메모와 완전 일치)

4. **모순 체크 보드 (선택 사항)**:
   - 다섯 기록을 모두 복원한 뒤, 기록의 주장 / 현장 메모와의 비교 / 진위 여부를 팀원들이 적어 내려갈 수 있는 A4 필기 서식. 웹 화면만으로도 진행에는 지장이 없으나, 팀 토론을 돕는 보조 도구로 원하면 사용한다.

## 7. QR 배치 및 현장 동선

- **QR 위치**: 본관 중앙 접수대 및 메인 로비 기둥 표지판
- **QR 접속 URL**: `game.html?stage=case`
- **동선 이동**:
  1. 본관 로비에서 QR 스캔 → `game.html?stage=case` 진입, 현장 사건 메모 확인.
  2. 로비 곳곳에 숨겨진 알파벳 암호 카드 A~E 5장을 수색하고, 찾을 때마다 웹의 해당 슬롯에 4자리 암호를 입력해 기록을 복원.
  3. 다섯 기록이 모두 복원되면 웹 화면에서 거짓 기록 3건 선택 및 `나그네` 입력.
  4. 진행자에게 완료 코드 `PILGRIM-00` 제시 후 키워드 카드 00(`나그네`) 수령.
  5. 00 오프닝 완료 후, 01~04 4개 스테이지(01 야외, 02 숙소, 03 창고 및 물자 보관소, 04 길)는 정해진 순서 없이 팀별 비선형 자유 탐색으로 진행.
  6. 5개 팀의 동선 겹침 및 병목을 예방하기 위해 00 완료 후 팀별 추천 출발 장소(A팀: 01 야외, B팀: 02 숙소, C팀: 03 창고 및 물자 보관소, D팀: 04 길, E팀: 자유 선택)로 교차 순환 출발.
  7. 01~04 4개 스테이지 키워드를 모두 모은 후 05 예배당으로 최종 결집.

## 8. 자물쇠 및 완료 코드 처리 (Lock & Code Handling)

- **물리 자물쇠**: 없음. 대신 알파벳 암호 카드 5장이 물리적 "열쇠" 역할을 한다 — 카드를 찾지 못하면 해당 기록 문장 자체가 웹에 나타나지 않는다.
- **올바른 진행 절차**:
  1. 참가자가 로비에서 알파벳 카드 A~E를 찾아 웹의 각 슬롯에 암호를 입력해 기록 5건을 모두 복원.
  2. 복원된 기록 5건과 사건 메모를 대조하여 거짓 기록 3건(`stampA`, `deskC`, `numberD`)을 선별.
  3. 웹 화면(`game.html?stage=case`)에서 거짓 기록 3건을 선택하고 `[거짓 기록 3건 확정]` 클릭.
  4. 정체성 입력창이 열리면 `나그네` 입력 후 `[정체성 확인]` 클릭.
  5. 웹 화면에 히브리서 11:13 구절과 완료 코드 `PILGRIM-00`이 출력됨.
  6. 진행자에게 `PILGRIM-00` 제시 시, 진행자가 실물 키워드 카드 00(`나그네`) 지급.
  7. 참가자는 활동 페이지(`activity.html`)에 `PILGRIM-00`을 입력해 공식 스테이지 00 해금 완료.

## 9. 웹 화면 구현 사양 및 상태 전이

### 웹 상태 흐름
1. `S0_HUNT`: 사건 메모 지침 표시, 접수 기록 5건이 잠금 상태로 대기(암호 입력 폼만 노출, 문장 비공개). 카드 암호를 정확히 입력할 때마다 해당 기록이 잠금 해제됨(`n/5 복원`).
2. `S1_INSPECT`: 다섯 기록이 모두 복원되면 선택형 기록 그리드로 전환, 거짓 기록 3건 선택 UI 노출.
3. `S2_IDENTITY`: 거짓 기록 3건(`stampA`, `deskC`, `numberD`) 올바르게 선택 시 정체성 텍스트 입력창 해금.
4. `S3_SOLVED`: `나그네` 입력 성공 시 히브리서 11:13 성경 구절 패널과 함께 완료 코드 `PILGRIM-00` 표시.

### 실패 피드백 문구
- 잘못된 암호 입력: `"그 암호로는 이 기록이 열리지 않습니다. 카드의 알파벳과 기록 이름이 맞는지 다시 확인하십시오."`
- 거짓 기록 선택 수 오류 (3개 미만/초과): `"거짓 기록은 정확히 3건입니다. 사건 메모의 지침과 비교해 보세요."`
- 잘못된 거짓 기록 선택: `"선택한 기록 중 진짜 기록이 포함되어 있습니다. 본관이 목적지인지, H를 지워도 되는지 다시 확인하세요."`
- 정체성 오답 입력: `"본관에 도착했지만 목적지가 기록되지 않은 우리를 성경은 뭐라고 부르는가? (H-11-13 참고)"`

## 10. 진행자 3단계 힌트 가이드 (3-Tier Hint Guide)

1. **시선 (Tier 1)**: `"본관 로비 곳곳에 숨겨진 알파벳 카드 A~E를 먼저 모두 찾으세요. 카드의 4자리 숫자가 같은 알파벳 기록을 여는 암호입니다."`
2. **대조 (Tier 2)**: `"다섯 기록을 모두 복원했다면, 도장 기록(stampA: 도착 도장 받음), 접수대 기록(deskC: 목적지 등록), 사건 번호 기록(numberD: H 지워도 됨)이 사건 메모와 모순되는 거짓 기록 3건입니다."`
3. **행동 (Tier 3)**: `"웹에서 stampA, deskC, numberD를 선택해 확정하세요. 사건번호 H-11-13은 히브리서 11장 13절('땅에서는 나그네와 외국인임을 증언하였으니')이 가리키는 정체성입니다."`

진행자는 힌트 3단계에서도 정답 단어 `나그네`를 직접 말하지 않는다.

## 11. 회차별 리셋 체크리스트 (Reset Checklist)

- [ ] 팀별 알파벳 암호 카드 A~E 5장이 정해진 위치(30~50cm씩 어긋난 5개 지점)에 팀 라벨과 함께 숨겨져 있는지 확인.
- [ ] 다른 회차/다른 팀 카드가 섞여 있지 않은지 뒷면 팀 라벨로 확인.
- [ ] 진행자 보관함에 키워드 카드 00(`나그네`) 5장이 완비되어 있는지 확인.
- [ ] 웹 테스트 기기 접속 초기화 확인(로컬/관리자 미리보기 링크로 사전 점검).

## 12. 진행자 정답표 & 운영 해설 (Facilitator Answer Key)

| 검수 항목 | 정답 및 상세 내용 |
|---|---|
| 접수 기록 5건 진위 | `stampA`(거짓/false), `listB`(진짜/true), `deskC`(거짓/false), `numberD`(거짓/false), `timeE`(진짜/true) |
| 웹 선택 거짓 기록 3건 | `stampA`, `deskC`, `numberD` |
| 웹 정체성 정답 | `나그네` |
| 성경 구절 근거 | 히브리서 11장 13절 (H-11-13: "또 땅에서는 나그네와 외국인임을 증언하였으니") |
| 결과 키워드 카드 | `나그네` (실물 카드) |
| 활동 페이지 완료 코드 | `PILGRIM-00` |
| 알파벳 카드 암호값(팀별) | `print-materials.html` "00 본관 5개 팀별 독자 보물찾기 암호 카드 마스터" 표 참고. 웹은 5팀의 모든 값을 정답으로 인정하므로 팀 구분 없이 어떤 팀 카드를 스캔해도 열림. |

### 운영 해설
참가자들이 "우리가 목적지에 도착했다"는 착각에서 벗어나 "아직 길 위에 있는 나그네"임을 깨닫는 것이 이 스테이지의 핵심 목적입니다. `PILGRIM-00` 코드를 확인하면 참가자들을 격려하며 01~04 스테이지 비선형 자유 탐색(교차 순환 순서)으로 안내하십시오.
