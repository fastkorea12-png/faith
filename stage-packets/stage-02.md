# 02 숙소 스테이지 패키지 — 빌린 이름

## 1. 고정 계약

| 항목 | 확정값 |
|---|---|
| 대상 | 대학생, 3~6명 1팀 |
| 목표 시간 | 12~18분(중앙값 15분) |
| 장르 | 팀 분업형 디지털 포렌식 / 기록 진위 판별 |
| 현장 | 숙소 문 앞과 그 주변(실제 객실 내부 및 투숙객 동선 사용 금지) |
| 핵심 장치 | QR로 여는 가상 휴대폰 |
| 잠금 암호 | `0316` |
| 결과 키워드 | `약속` |
| 완료 코드 | `PROMISE-02` |
| 핵심 반전 | 주인이 붙들었던 정체성은 ‘성공한 사람/인정받는 사람’이라는 이름표가 아니라, 바뀌지 않은 약속에서 드러난다. |
| 성경 지식 | 불필요. 화면과 현장 기록만으로 완결되어야 한다. |

`0316`, `약속`, `PROMISE-02`는 각각 서로 다른 용도다. `0316`은 휴대폰을 여는 숫자이고, `약속`은 팀이 회수할 키워드이며, `PROMISE-02`만 활동 페이지에 입력한다. 세 값을 서로 대신 입력하게 만들지 않는다.

## 2. 플레이어 경험과 사건 개요

숙소에서 발견된 휴대폰의 주인은 자신을 ‘성공한 사람’, ‘인정받는 사람’이라고 여러 번 저장해 두었다. 알림과 사진만 보면 그중 하나가 진짜 이름처럼 보인다. 그러나 기록의 생성 시점과 상태를 대조하면 두 이름은 행사 때마다 갈아 붙인 **임시 이름표**이고, 유일하게 수정되지 않은 기록은 3월 16일의 약속 카드임이 드러난다. 마지막 메모에서 “빌린 이름은 바뀌지만 약속한 날은 바뀌지 않는다”는 고백을 복원한다.

오해는 가짜 이름이 자주 등장하고 사진에서도 강조되어 생긴다. 반전은 단순한 교훈 문구가 아니라 다음 세 증거로 검증한다.

1. 알림은 비밀번호의 자료와 형식을 각각 `문 앞 안내문`과 `MMDD`로 한정한다.
2. 사진은 이름표 두 장에 `임시`, 약속 카드에 `원본/수정 없음`이라는 서로 다른 상태를 보여 준다.
3. 메모의 수정 이력은 이름 두 개가 지워진 뒤에도 `약속`만 남았음을 확정한다.

## 3. 팀 분업 구조

QR을 연 직후 화면에 세 역할을 제안한다. 역할 선택은 강제하지 않지만, 한 사람이 화면을 독점해서는 제한 시간 안에 모든 근거를 비교하기 어렵게 구성한다.

| 역할 | 담당 행동 | 반드시 공유할 정보 |
|---|---|---|
| 알림 분석관 | 잠금화면 알림의 발신자, 지시어, 암호 형식을 읽고 기록 | “문 앞”, “약속한 날”, `MMDD` |
| 현장 감식관 | 문 앞 안내문과 분리 배치된 증거표 3장을 찾아 상태·날짜 확인 | 약속 카드 `03/16`, 이름표는 `임시`, `11:13`은 퇴실 시각 |
| 기록 대조관 | 팀 포렌식 기록지에 후보와 근거를 적고 사진·메모 앱의 이력을 대조 | 무엇이 반복 노출됐는지와 무엇이 수정되지 않았는지 |

4명 이상이면 현장 감식관을 2명으로 나누어 이름표 증거와 날짜 증거를 동시에 찾는다. 휴대폰을 조작하는 사람은 다른 팀원이 근거를 말한 뒤에만 선택·입력하도록 시작 안내에 명시한다.

## 4. 현장 준비물 및 배치

### 참가자용

| 준비물 | 수량 | 내용 및 제작 규격 | 배치 |
|---|---:|---|---|
| 스테이지 QR 카드 | 1 | `stage=name` 현장 진입 QR, “분실 휴대폰 사건파일” 표기 | 숙소 문 밖 조사 시작점 |
| 숙소 문 앞 안내문 | 1 | `약속 카드 수령일 03/16`, `퇴실 안내 11:13`; 두 항목을 같은 크기·색으로 인쇄 | 숙소 문 앞 |
| 임시 이름표 증거 | 2 | `성공한 사람`, `인정받는 사람`; 앞면은 그럴듯하게, 뒷면에 각각 `임시 발급 / 반납 대상` 도장 | 문 주변 서로 다른 위치, QR에서 3~8m 이내 |
| 약속 카드 증거 | 1 | `수령일 03/16`; 뒷면에 `원본 / 수정 없음` 도장 | 안내문 근처지만 이름표와 겹치지 않게 배치 |
| 팀 포렌식 기록지 | 팀당 1 | 후보, 기록 종류, 상태, 날짜/시간, 결론 칸 | QR 카드 옆 클립보드 |
| 필기구 | 팀당 2 | 서로 다른 역할이 동시에 기록 가능 | 클립보드 |
| 키워드 카드 | 1 | 앞면 `약속`, 뒷면 `02`; 완료 후 진행자 또는 현장 보관함에서 수령 | 진행자 보관 또는 완료 지점 |

실제 4자리 자물쇠 봉투는 필수 풀이 장치로 쓰지 않는다. 이 스테이지는 설계 원칙의 예외인 **가상 장치 해킹**이며 `0316`은 웹에 한 번만 입력한다. 기존 운영 물품표 때문에 4자리 자물쇠 봉투를 유지해야 한다면, 암호 검증용으로 중복 사용하지 말고 충전 케이블·기록지·키워드 카드 보관용 무잠금 소품으로만 사용한다.

### 진행자용

- 정답표 1부: `0316 → 약속 → PROMISE-02`
- 증거 배치 사진 1장과 회수 체크리스트 1부
- 분실·훼손 대비 안내문, 이름표, 약속 카드 각 1장
- 네트워크 장애 대비 오프라인 캡처 4장(잠금화면, 알림, 사진, 메모)과 수동 완료 코드 카드 1장
- 12분/15분/18분 타이머 및 힌트 사용 기록표

흑백 출력에서도 상태를 구분하도록 색만 쓰지 않고 `임시 발급`, `원본`, `수정 없음`, `반납 대상`을 글자와 테두리 모양으로 함께 표시한다.

## 5. 웹 화면 상태 계약

앱은 자유 탐색형 아이콘 모음으로 처음부터 열지 않는다. 아래 상태를 순서대로 진행한다. 새로고침 시 현재 상태를 복구하되 암호 입력값 자체는 저장하지 않는다.

| 상태 ID | 화면과 가능한 행동 | 해금 조건 | 저장할 상태 |
|---|---|---|---|
| `S0_LOCKED` | 잠금화면, 알림 배너 2개, `알림 조사` 버튼만 활성 | QR 정상 진입 | 시작 시각 |
| `S1_NOTICE` | 알림 앱 전체 보기. 엄마: “약속한 날은 문 앞 기록에”, 룸메이트: “형식은 MMDD”; 후보 기록표 표시 | 알림 두 개를 모두 펼침 | 알림 확인 2개 |
| `S2_FIELD` | 암호 키패드와 “현장 증거를 대조하라” 안내. 현장 후보를 화면에서 고르는 리허설용 버튼은 참가자 모드에서 숨김 | 두 알림 확인 | 암호 시도 횟수 |
| `S3_PHOTO` | `0316` 성공 후 홈 화면. **사진 앱만 활성**, 알림은 읽기 전용, 메모는 잠금 표시 | 정확히 `0316` 입력 | 휴대폰 해제 |
| `S4_COMPARE` | 사진 3장: 성공 이름표, 인정 이름표, 약속 카드. 각 사진의 상태/촬영 시각을 확대하고 “원본으로 남은 기록” 하나 선택 | 사진 3장 모두 확대 | 사진 확인 3개, 선택값 |
| `S5_MEMO` | 올바르게 약속 카드를 선택하면 메모 앱 활성. 삭제선이 있는 두 이름과 최종 문장 복원 | 약속 카드 선택 | 메모 해제 |
| `S6_SOLVED` | 키워드 `약속` 공개 후 완료 코드 `PROMISE-02` 표시, 활동 페이지 이동 버튼 | 메모 마지막 줄을 탭해 복원 | solved, keyword |

현재 기준선 `game.js`와의 구현 차이는 명확히 유지한다.

- 현재는 `0316` 해제 후 모든 앱이 동시에 열리지만, 목표 구현은 `사진 → 메모` 순차 해금이다.
- 현재 화면 안에 현장 안내문 후보 버튼이 보이지만, 참가자 모드에서는 제거하고 관리자 미리보기에서만 표시한다.
- 현재 검색 앱은 필수 근거가 아니므로 제거하거나 관리자용 보조 기록으로만 둔다.
- 현재는 메모 앱을 누르는 즉시 완료되지만, 목표 구현은 사진 3장 대조와 올바른 원본 선택을 선행한다.

접근성상 잠긴 앱에는 색 변화만 주지 말고 자물쇠 아이콘, `사진 기록을 먼저 검증하세요` 문구, 비활성 속성을 함께 적용한다. 390px 폭에서 키패드, 사진 상태표, 완료 코드가 가로 스크롤 없이 보여야 한다.

## 6. 정확한 풀이 경로

1. 팀이 QR을 스캔해 `S0_LOCKED`에 진입하고 역할을 나눈다.
2. 알림 분석관이 두 알림을 모두 펼쳐 **자료는 문 앞의 약속한 날**, **형식은 MMDD**라고 팀에 전달한다.
3. 현장 감식관들은 안내문, 이름표 2장, 약속 카드의 앞·뒷면을 찾아 기록지에 옮긴다.
4. 기록 대조관은 후보를 분류한다.
   - `성공한 사람`, `인정받는 사람`: 날짜가 아니며 뒷면이 `임시 발급 / 반납 대상`이므로 암호 후보에서 제외한다.
   - `11:13`: 숫자지만 `퇴실 안내`의 시각이고 MMDD 형식이 아니므로 제외한다.
   - `03/16`: `약속 카드 수령일`이며 MMDD로 변환 가능한 유일한 기록이다.
5. 팀이 `03/16 → 0316`으로 변환해 가상 키패드에 입력한다. 휴대폰이 `S3_PHOTO`로 열린다.
6. 사진 앱의 세 사진을 나누어 확대한다. 이름표 사진은 눈에 띄고 반복되지만 상태가 `임시/반납`, 약속 카드 사진은 `원본/수정 없음`임을 확인한다.
7. 팀은 “원본으로 남은 기록”으로 약속 카드를 선택한다. 이 선택으로 메모 앱이 열린다.
8. 메모에서 `성공한 사람`, `인정받는 사람`이 삭제된 편집 이력과 “바뀌지 않은 것은 약속”이라는 마지막 줄을 복원한다.
9. 화면이 키워드 `약속`과 완료 코드 `PROMISE-02`를 분리해 보여 준다. 팀은 키워드 카드를 받고 활동 페이지에는 `PROMISE-02`만 입력한다.

필수 추론은 모든 단서에 쓰여 있으며 성경 구절, 인물, 장·절을 알아야 하는 단계가 없다. `11:13`은 다른 스테이지의 의미를 추측하게 하는 숫자가 아니라, 이 스테이지 안에서 명시적으로 ‘퇴실 시각’이라 배제된다.

## 7. 실패 피드백

실패는 정답을 노출하지 않고 잘못 사용한 근거의 종류를 알려 준다. 같은 실패를 세 번 반복하면 해당 단계의 다음 힌트를 진행자 화면에 권고한다.

| 실패 | 즉시 웹 피드백 | 회복 행동 |
|---|---|---|
| 4자리 미만/초과 입력 | “잠금 기록은 네 자리 MMDD 형식입니다.” | 알림 형식 재확인 |
| `1113` 입력 | “그 숫자는 날짜가 아니라 퇴실 **시각**으로 분류되어 있습니다.” | 안내문의 항목명 대조 |
| 그 밖의 오답 암호 | “숫자는 맞는 모양보다 출처가 중요합니다. ‘약속한 날’의 수령 기록을 찾으세요.” | 약속 카드와 안내문 대조 |
| 이름표 사진 선택 | “많이 찍힌 기록이 원본이라는 뜻은 아닙니다. 사진의 상태 도장을 확대하세요.” | `임시/반납`과 `원본/수정 없음` 비교 |
| 잠긴 메모 앱 선택 | “메모의 봉인이 남아 있습니다. 사진 기록의 진위를 먼저 확정하세요.” | 사진 앱으로 복귀 |
| 완료 코드 대신 `0316` 입력 시도 | 완료 화면에 “0316은 휴대폰 암호였습니다. 활동 페이지에는 사건 완료 코드를 입력하세요.” | `PROMISE-02` 복사/확인 |

오답 횟수로 게임을 초기화하거나 일정 시간 입력을 막지 않는다. 오류 후에도 이미 확인한 알림·사진 상태는 유지한다.

## 8. 진행자 힌트 3단계

힌트는 현재 막힌 단계에 맞춰 한 단계씩만 제공한다.

1. **시선 주기:** “잠금화면의 두 알림에서 장소를 가리키는 말과 숫자의 형식을 각각 한 개씩 찾아보세요.”
2. **대조 지시:** “숙소 문 앞 기록에서 이름과 시각은 잠시 빼고, ‘약속한 날’에 해당하는 날짜를 찾아 MMDD와 대조하세요.”
3. **행동 직전:** “약속 카드 수령일 3월 16일에서 슬래시를 빼 네 자리로 입력하세요. 열린 뒤에는 사진 세 장의 상태 도장을 비교하세요.”

사진 단계에서 별도 보충이 꼭 필요하면 새 힌트 단계를 만들지 않고 현재 단계의 뒤 문장만 읽는다: “반복해서 보이는 이름보다 `임시/반납`과 `원본/수정 없음`을 비교하세요.”

## 9. 시간 설계

| 구간 | 목표 누적 시간 | 관찰 포인트 |
|---|---:|---|
| 브리핑·역할 분담·알림 확인 | 0~3분 | 두 알림을 서로 다른 사람이 읽는가 |
| 현장 증거 탐색·기록 | 3~8분 | 최소 2명이 동시에 움직이는가 |
| 암호 추론·입력 | 8~11분 | `11:13`을 항목명으로 배제하는가 |
| 사진 진위 대조 | 11~14분 | 빈도보다 상태를 근거로 드는가 |
| 메모 반전·완료 코드 | 14~16분 | 세 값의 용도를 구분하는가 |

12분 이내 완료해도 사진 증거를 모두 열지 않고 찍은 팀이면 성공으로 판정하지 않는다. 18분에 도달하면 진행자가 현재 단계에 맞는 다음 힌트를 즉시 제공하고, 20분에는 운영 흐름을 위해 3단계 힌트와 증거 위치를 안내한다.

## 10. 플레이테스트 기준

### 테스트 구성

- 대학생 3~6명 팀 최소 3회, 총 참가자 12명 이상
- 이 중 성경 배경지식이 없다고 응답한 참가자 최소 1팀
- 390px 안팎 모바일 1회 이상, iOS/Android 각각 1회 이상
- 참가자 QR 정상 진입, 관리자 미리보기, 새로고침/뒤로가기, 네트워크 지연을 각각 확인

### 통과 기준

| 지표 | 통과선 |
|---|---|
| 완료 시간 | 팀의 80% 이상이 12~18분에 완료, 중앙값 14~16분 |
| 무힌트 해결 | 60% 이상 |
| 힌트 상한 | 모든 팀이 힌트 2 이하로 20분 안에 완료 |
| 분업 | 팀마다 최소 3명이 서로 다른 증거를 읽거나 기록·입력에 기여 |
| 공정성 | 완료 후 80% 이상이 `0316`의 근거를 “약속 카드 수령일 + MMDD”로 설명 |
| 반전 이해 | 80% 이상이 이름표가 가짜인 근거를 `임시/반납`, 약속이 진짜인 근거를 `원본/수정 없음`으로 설명 |
| 코드 일관성 | 전원이 `0316`, `약속`, `PROMISE-02`의 용도를 구분 |
| 비성경 의존성 | 성경 지식이 없는 팀도 추가 설명 없이 해결 |
| 모바일 안정성 | 390px에서 겹침·잘림 없음, 탭 대상 최소 44px, 키패드 오입력 후 복구 가능 |
| 상태 복구 | `S1`~`S6` 각 상태에서 새로고침 후 해금 순서가 건너뛰거나 되감기지 않음 |

### 반드시 기록할 관찰

- 첫 2분 동안 한 명이 화면을 독점했는지
- 이름표를 진짜 이름으로 믿은 순간과 그 근거
- `11:13`을 날짜로 오인했는지, 항목명만으로 회복했는지
- 사진 세 장 중 무엇을 먼저 열었는지
- 메모 반전 전에 이미 `약속`을 확신했는지
- 오답 문구가 정답을 누설하지 않고 다음 관찰을 유도했는지
- 키워드와 완료 코드를 혼동했는지

두 팀 이상이 같은 필수 증거를 발견하지 못하면 위치나 인쇄 대비를 수정한다. 두 팀 이상이 이름표를 근거 없이 버리면 가짜 이름의 노출 빈도를 높인다. 두 팀 이상이 사진 앱을 거치지 않고 메모로 완료하면 상태 전이 결함으로 보고 출시를 막는다.

## 11. 구현·인쇄 인계 체크리스트

- [ ] 참가자 모드에서 현장 후보 선택 버튼을 숨겼다.
- [ ] `알림 → 현장 대조/0316 → 사진 → 메모 → 완료` 순서가 강제된다.
- [ ] 사진 세 장을 모두 확인해야 원본 선택이 가능하다.
- [ ] 메모는 올바른 사진 선택 전에는 열리지 않는다.
- [ ] 정답 `0316`, 키워드 `약속`, 완료 코드 `PROMISE-02`가 웹·활동 페이지·진행자표·키워드 카드에서 일치한다.
- [ ] 성공 시에만 `homeward-solved-name=true`, `homeward-keyword-name=약속`을 저장한다.
- [ ] 오답, 새로고침, 뒤로가기, 관리자 미리보기를 검수했다.
- [ ] 숙소 문 앞 안내문과 세 증거의 문구가 웹 사진의 상태 정보와 글자 단위로 일치한다.
- [ ] 흑백 인쇄와 3~8m 탐색 범위에서 현장 테스트했다.
- [ ] 실제 투숙객 공간을 침범하지 않고 모든 증거를 회수할 수 있다.
